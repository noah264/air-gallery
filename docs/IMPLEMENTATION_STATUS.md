# AirGallery 实现状态

更新：2026-11-05 · v0.1.8

当前交付为可运行原型，包含 React / TypeScript / Three.js 共享界面与 Electron 桌面壳。产品目标仍以产品需求文档为准，本文件描述实际范围。

## 发布流程

- `main` 推送运行核心测试、生产构建与完整浏览器回归，通过后自动部署 GitHub Pages。
- `v*` 标签触发 macOS arm64 / x64 DMG、Windows x64 NSIS 安装包与 Web 压缩包构建；全部成功后统一发布 GitHub Release，并附 SHA-256 校验值。
- 桌面版本尚未配置签名、公证或自动更新；Windows CI 构建成功也不代表已完成 Windows 实机体验验证。
- v0.1.7 的 macOS arm64 / x64 和 Windows x64 均已在对应系统的 GitHub Actions 中打包成功；安装包、Web 静态压缩包与 SHA-256 校验文件已发布至 [GitHub Release](https://github.com/noah264/jetson-photo-wall/releases/tag/v0.1.7)。
- [v0.1.7 发布说明](./releases/v0.1.7.md)。

## 已实现

- 本机目录递归分组，JPG / PNG / WebP，文件名自然排序，首图封面与多页照片叠。
- 椭圆空间分布，中心画册放大、名称与邻近画册留白；连续缩放、平移、恢复总览。
- 单图查看、翻页、独立缩放和平移；返回空间保留视图。
- 六种玻璃背景主题，预览、取消、应用、跟随系统与偏好保存。
- Web 目录授权、句柄保存、15 秒可见时扫描、焦点刷新；文件夹选择兼容模式。
- 桌面目录选择、保存和监听；受限 IPC 与图片协议，本机原图按需读取。
- 用户主动开启摄像头；本机 Worker 推理，单手选择/拖动、双手缩放、挥手翻页；关闭时停止摄像头轨道。

## v0.1.8 空间悬浮与拍手修正

- 每本画册使用独立相位缓慢漂移和轻微摆动；中心画册名称跟随其实际位置。移动幅度保留现有留白，放大时同步收小位移和转角，避免高倍缩放时大幅晃动。
- 封面加载后才启动共享悬浮时钟，最高请求约 30 次重绘/秒；根据渲染耗时留出空闲间隔，逐帧修改 Three 对象而不更新 React 状态。照片页、设置、首页烟花、页面隐藏时暂停空间渲染；减少动态效果时回到静止状态。示例单帧绘制预算仍为 129 次。
- 修复拍手仅在照片页生效的限制：首页也能放烟花，F 键均可预览。切换画册、翻页、打开设置或结束播放后清理效果与声音。
- 双掌姿态结合深度判断，减少侧掌的投影压缩影响；检测、存在和追踪置信度使用 0.5。支持先分开再快速收拢，接近时短暂单手遮挡可结合已验证的速度和位置确认；双手完全丢失不会直接触发。普通丢手、长时间停顿、慢慢合拢和捏合缩放仍不触发。
- 开启摄像头后显示追踪状态及操作提示；权限或识别失败会给出提示。摄像头默认关闭，不新增麦克风、录像或上传。
- 本地 34 项核心测试、11 项端到端测试和生产构建通过，覆盖悬浮、名称跟随、减少动态静止、背景停绘、首页侧掌/遮挡拍手以及照片页烟花链路。手势回归使用合成关键点，不是实机识别准确率数据。

## v0.1.7 菜单淡入淡出

- 设置中的外观、图片目录、手势与操作页面切换时，当前内容先淡出 110ms，新内容再淡入 180ms；菜单文字颜色同步平滑变化。
- 连续点击时使用最后选择的目标；淡入中再次切换会从当前透明度继续淡出。淡出内容暂停交互，切换后回到页面顶部；主题草稿与摄像头状态保持。
- 尊重减少动态效果偏好，开启后直接切换；动画完成由浏览器事件驱动，无额外计时器或持续渲染。
- 生产构建及现有 3 项界面端到端回归通过，覆盖主题预览／取消／保存、目录切换与相机开关；macOS v0.1.7 已打包并打开，原生窗口已确认目录、手势页面切换后正常显示。清理 v0.1.6 旧包，release 仅保留 v0.1.7。

## v0.1.6 持续点赞与随机弹幕

- 点赞改为持续状态：只要识别到单手 👍 就持续下雨，取消 600ms 保持确认、单次锁存和 2.5 秒冷却。松手后不再生成，已有文字自然落完，重新点赞立即继续。
- 每 320ms 按视口宽度分批生成；每条独立随机选择 24 句夸奖、配色、字号、速度和摆动。过期节点回收，标准模式同时最多 160 条，不随持续时间增长。
- 摄像头关闭、丢手、过期结果或识别中断会停止新增；350ms 未收到有效识别结果时自动停发。设置页与后台暂停；照片翻页、返回空间时可以继续保持下雨。
- 减少动态效果时使用最多 12 张静态夸奖卡片，约 2 秒随机刷新。P 键仍为约 8 秒的有限预览。
- 29 项核心测试、10 项端到端测试与生产构建通过。连续点赞超过旧的 8.2 秒后仍有新随机文字，旧节点已回收且叠层不重复创建；验证松手停发、自然落完、再次点赞、线程停顿保护、翻页操作及减少动态效果。识别链路测试使用合成关键点。
- macOS arm64 v0.1.6 已打包并打开，原生窗口已确认更新后的操作说明与随机下落画面。按用户要求清理 release/mac-arm64 和 v0.1.1 至 v0.1.5 六份旧包及旧构建日志；release 仅保留 v0.1.6。

## v0.1.4 大型花火与密集拖尾

- 烟花升级为约 7.2 秒、10 束错落连发，结尾三束齐放。四种花型为三层菊花、粉紫牡丹、冰蓝花冠与金色垂柳，带升空轨迹、星芒与余光。
- 标准模式每束 580 条发光尾迹，10 束共呈现 5800 条；最大花冠名义直径为视口短边的 112%，允许向画面边缘延伸。这是图层中的绘制线条数量，不是同时模拟的粒子数量。
- 四种花型预绘为可复用图层，逐帧只执行扩散、图层下坠与渐隐合成；像素比上限 1.5。退出、翻页、重播或结束时释放临时画布与音频，不在后台持续绘制。
- 减少动态效果时每束降为 72 条尾迹，尺寸缩小、扩散减缓，隐藏升空和闪光。播放中静音不会重置动画。
- 音效与新的 10 束时间线同步，整体增益下调；离线渲染峰值约 0.209、RMS 约 0.022，输出非静音且未削波。
- 24 项核心测试、8 项端到端测试及生产构建通过。新增受控时间的画面覆盖与减少动态效果回归；macOS arm64 v0.1.4 包已生成并打开，原生照片页已目视确认大型三层烟花。[连发收尾截图](./design/airgallery-fireworks-v0.1.4.png)。本轮未测量实机 FPS，不据图层数量推断固定帧率。

## v0.1.3 拍手烟花与音效

- 在照片查看页，双掌先分开再快速合拢拍手，触发当前照片上方约 4 秒的烟花动画；首页不触发。通过摄像头的掌心位置、掌宽归一化距离和合拢速度判断，无需麦克风。
- 双手捏合缩放、静止合掌、缓慢靠拢、丢手、识别长停顿及双掌上下错开不作为拍手。两只张开的手在照片查看页保留给拍手，不同时触发挥手翻页。
- 约 2.2 秒识别冷却，一次动作仅触发一次；重新拍手需要先再次分开双掌。重复触发替换当前动画，不叠加无限粒子或声音。
- Canvas 透明层呈现升空轨迹、五束不同颜色烟花与余火，保留原图；最多 450 个粒子，像素比上限 1.5，只在播放期间绘制。减少动态效果偏好会降低粒子数、扩散范围并隐藏升空轨迹。
- Web Audio 本机合成升空、低频爆破、过滤噪声与余火噼啪音效，不依赖在线音频素材。首次按键/点击时解锁播放；查看器可关闭音效并记住选择。
- 提供 F 键及查看器烟花按钮作为预览入口，不需要摄像头。翻页、退出查看或页面隐藏时清理动画、停止声音；播放中静音立即停止声音。
- 新增 5 项拍手逻辑测试，以及音频/播放生命周期和完整拍手到当前照片烟花的端到端测试。合成关键点不是识别准确率数据，实机拍手时需让双掌完整入镜、保持大致同一高度。
- 离线音频渲染测得峰值约 0.239、RMS 约 0.027（单位为满幅），确认输出非静音且未削波；实际响度依赖用户设备音量，未做真人听感测评。
- 本轮 24 项核心测试、7 项端到端测试、生产构建通过；macOS arm64 v0.1.3 包已生成并打开到照片查看页。真实摄像头拍手识别率仍需实测。[运行截图](./design/airgallery-fireworks-v0.1.3.png)。

## v0.1.2 打开与关闭图集手势

- 单手比 V 并保持约 600ms，打开中心选中的画册；不需要再次用手指瞄准小图。
- 单手握拳并保持约 600ms，关闭图集并恢复原空间视图。
- 取消“连续两次捏合打开”，单手捏合只负责选择和平移。
- 画面短暂显示动作及圆环进度。第二只手入镜、改变姿势、移动过大、丢手、长时间识别停顿或打开设置会取消本次计时。
- 进度完成只触发一次，保持同一姿势不连发；V 仅在空间模式生效，握拳仅在组内模式生效，避免误切换。
- 姿势根据现有手部关键点判断，不新增识别模型，也不采集或训练用户视频。合成关键点用于逻辑回归，不代表真实手势识别率。
- 本轮 19 项核心测试、5 项端到端测试及生产构建通过。新增回归覆盖姿势区分、保持计时、取消、模式限制、双手互斥、不连发，以及从摄像头调度到进度提示、打开/返回并保留空间视图的完整链路（使用合成关键点）。真实模型启动由独立模拟摄像头用例覆盖。

## v0.1.1 流畅度优化

手势输入：

- 取消固定 65ms 的采样上限，优先按视频新帧调度，目标最高约 30 次/秒；慢设备根据推理耗时降低采样频率，始终只有一帧在途，避免排队。
- 输入最长边 480px，减少截图传输开销；不重复识别同一视频帧，后台暂停取帧。
- 按位置匹配前后帧的手，减少模型输出顺序变化引起的跳动。
- 使用速度自适应低通滤波；捏合进入/退出使用不同阈值并确认持续时间；拖动有微小移动死区，缩放限制单帧突变。
- 超过 180ms 的过期结果不驱动画面；丢手或停顿后重新建立动作起点。
- 相机与单图在显示帧之间插值，平滑动画直接更新 Three 对象/图片变换，不每帧触发 React 状态更新。

渲染与布局：

- 布局避碰从所有画册两两比较改为附近网格比较。
- 共用平面几何与阴影纹理；外围保留两张纸质叠页，选中画册保留完整图片叠层。
- WebGL 像素比上限从 2 降到 1.5，减少高分屏绘制量；不模糊照片纹理。
- 离开视口与预留区的画册卸载，减少放大后的纹理与场景开销；单图查看期间停止背后的空间渲染。
- 保留按需绘制，静止时不持续刷新场景。

- 13 项核心测试通过，含缩放锚点、连续缩放、选中留白、目录排序、手势模式互斥、滤波、捏合迟滞、手部顺序变化与长停顿。

- 增加 WebGL 绘制预算与后台暂停回归：25 本示例画册每帧最多测得 129 次 drawElements；打开单图后绘制计数停止，退出后恢复。旧结构在全部可见且纹理就绪时为 225 次绘制，前后结构预算减少约 43%；这不是 FPS 提升百分比。
- v0.1.1 macOS arm64 包已生成并打开，原生窗口中已目视确认画册与设置显示。独立 Electron 自动化脚本仍在设置页鼠标点击时超时，尚未据此确认完整的桌面目录监听/重启恢复回归；这些不能记为本轮通过项。
- macOS / Node 24，同样的 3000 本合成画册，各执行 5 次：旧布局 770/583/678/671/645ms，新布局 88/84/118/85/84ms，中位数约快 7.9 倍。25 本画册的网格开销没有收益，主要解决大目录切换的主线程长任务。此数据仅为布局耗时，不是整体页面帧率。

## 当前限制与下一步实测

- 真实摄像头的准确率、延迟、逆光、双手遮挡和不同距离仍需实机验证；平滑阈值是首轮参数，未用用户视频训练或采集数据。
- Windows 运行和安装包尚未进行实机验证；macOS 原生玻璃与 Web 页面内玻璃效果不同。
- 桌面包尚未配置发布签名、自动更新和正式图标。
- 大目录总览仍需加载较多封面；尚未完成万级画册的实例化渲染和完整 GPU/内存基准。
- “无限缩放”采用连续对数尺度，保留 1e-12 至 1e12 的数值保护，不承诺数学上的无界精度。
- Web 文件夹兼容模式不保存目录授权、不能自动监听变化，需要重新选择。

方案依据：[React Three Fiber 性能指南](https://r3f.docs.pmnd.rs/advanced/scaling-performance)、[MediaPipe Web Hand Landmarker](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js)。参数与效果判断来自本项目实现和上述测试，未承诺所有设备达到固定帧率。
