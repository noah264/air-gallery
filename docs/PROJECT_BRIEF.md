- 日期：2026-11-04
- 版本：v0.11
- 最近更新：2026-11-05
- 阶段：v0.1 原型开发与验证；当前交付范围见[实现状态](./IMPLEMENTATION_STATUS.md)。
- 产品主文档：[空间画册产品需求 v1.2](./PRODUCT_REQUIREMENTS.md)。本文保留立项范围，产品交互细节以主文档为准。

## 1. 项目目标

开发一个视觉表现突出、可通过摄像头捕捉手势操作的空间画册，支持 macOS、Windows 和 Web。用户能够连续缩放和平移整个画册空间、选择画册、组内翻页及放大单张图片，并获得即时、清晰的视觉反馈。

## 2. 已确认需求

1. 图片浏览是核心用途。
2. 界面需要炫酷，具备有辨识度的视觉和动效。
3. 通过摄像头捕捉手势，实现放大、下一张、翻页等操作。
4. 支持 macOS、Windows、Web 三个平台。
5. 先完成立项讨论，再确定技术方案与开发计划。
6. 通过设置图片目录自动加载图片，无需逐张导入。
7. 图片来自当前使用的这台电脑；Web 端也直接浏览浏览器所在电脑的本机目录。
8. 视觉偏好为空间感，优先采用有纵深的照片展厅体验。
9. 图片可能按组组织；每组默认展示第一张，以多层照片叠放表现组内多页。
10. 首页以图片为主体，布局更自由、错落、有混沌感；替代规整弧形照片墙及常驻工具栏的设计。选中画册的文件夹名称作为唯一的常态文字例外。
11. 照片组从中间向周围扩散，中心拥挤、外围宽松，整体形成横向椭圆；椭圆中间有照片，不是空心环。
12. 中心被选中的照片组明显放大，与周围照片组保持清楚的边距；邻近组让位，不遮挡或贴住选中组。
13. 被选中画册上方展示半透明的文件夹名称；名称随选中画册更新，未选中的画册不显示名称。
14. 整个空间画册支持无限缩放，独立于单图缩放；以持续缩放体验为目标，极端尺度的行为与稳定性需经原型验证。
15. 背景采用偏苹果风格的半透明玻璃质感，替代不透明近黑底；照片层保持清晰。
16. 背景支持多套可配置主题；首版建议 6 套玻璃主题、设置预览与偏好保存，具体规则见产品主文档 6.5。

## 3. 首版范围建议（待讨论）

| 模块 | 首版内容 |
| --- | --- |
| 图片目录 | 设置图片目录后自动扫描并加载，直接读取源文件，无需逐张导入；优先支持 JPEG、PNG、WebP |
| 目录更新 | 建议记住目录配置，启动时重新扫描；运行期间自动发现新增、删除的图片，提供手动刷新入口；子目录与 Web 权限策略待确定 |
| 分组浏览 | 首页展示各组第一张及叠页效果，选中组后浏览组内图片；组的识别规则与首张排序待讨论 |
| 空间导航 | 整个空间连续无限缩放、锚点缩放、平移和恢复总览；打开及关闭画册后恢复空间状态 |
| 单图浏览 | 上一张／下一张、放大／缩小、放大后平移、恢复适配窗口 |
| 手势控制 | 手势开关、首次引导、状态提示、切图、缩放、翻页 |
| 视觉效果 | 沉浸式背景、具有层次的图片布局、流畅过渡、手势反馈 |
| 背景主题 | 建议提供雾紫晨光、冰川蓝、月光银、玫瑰暮色、森林薄雾、深空石墨；支持预览应用、取消恢复与本机偏好保存 |
| 基础操作 | 鼠标、触控板、键盘提供对应操作；摄像头不可用时仍可浏览 |
| 平台交付 | Web 访问，以及 macOS、Windows 可安装应用；最低系统与浏览器版本待验证 |

首版暂不纳入：账户体系、云端相册同步、多人协作、图片编辑、人脸识别、移动端适配、专用硬件集成。需要时再讨论扩展。

### 目录浏览流程

首次设置图片目录 → 自动扫描并识别分组 → 展示各组封面照片叠 → 选组并手势浏览组内图片。后续启动目标为恢复已配置目录并重新扫描；权限失效或目录不可用时提示重新选择。原图保留在原目录，应用仅维护必要的配置、索引与缩略图缓存。可考虑按子目录识别分组，但尚未确认；“第一张”采用何种排序也需明确。

桌面端通过本机文件访问能力读取目录；Web 端通过用户主动选择并授权目录后读取本机图片。远端图片服务不作为首版图片来源。

Web 的目录选择 API 存在浏览器兼容性限制，且需要用户交互触发。目录授权恢复、变化检测与降级方案需在技术选型时验证；暂不承诺所有浏览器都能静默恢复权限或实时监听本机目录。参考：[MDN：showDirectoryPicker](https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker)。

## 4. 手势交互草案（需原型验证）

| 用户意图 | 候选交互 | 约束 |
| --- | --- | --- |
| 上一张／下一张 | 单手向左／向右挥动 | 仅在单图浏览时生效；方向映射通过使用测试确定 |
| 组间导航 | 候选为单手向左／向右挥动 | 仅在空间模式解释为焦点切换；与空间拖动方案比较后确定 |
| 连续缩放 | 双手捏合后改变间距 | 空间模式缩放整个空间，组内模式缩放当前图；从当前倍率接续 |
| 平移 | 捏合并拖动 | 空间模式移动视野，组内模式查看放大图局部；与切图动作互斥 |
| 恢复视图 | 明确的静态手势或屏幕按钮 | 动作与停留时长待验证 |
| 启用／暂停识别 | 首版提供明确的界面开关 | 后续再评估手势唤醒 |

交互原则：明确区分“未检测到手、正在识别、操作已触发”；通过置信度门槛、连续帧确认、动作结束判定和冷却机制减少误触。手部短暂丢失时保持当前画面，避免突然缩放或翻页。

“下一张”定义为组内图片切换；首页以叠放照片表现多页。组内切换是否采用纸页翻动动画仍待确认；组间导航与组内翻页应使用明确的交互状态区分。

## 5. 视觉方向：自由散落的空间照片叠

已确认用户偏好空间感、分组叠页与图片为主的首页，并要求布局更混沌；选中画册上方显示半透明文件夹名称。以下具体设计作为首版建议，替代 v1 规整弧形展厅：

- **总览**：每组只展示第一张封面，后方露出数层偏移、轻微旋转的照片边缘；各组以不同大小、角度和深度，从中间向四周错落扩散。中心照片组较拥挤，向外间距逐渐增大，整体构成横向椭圆；保留随机感，无网格、规则同心圈或空心环形轨道。
- **聚焦**：选中的照片叠移至中心并明显放大，四周保留空白边距；周围组平滑让位，不能遮挡或贴住选中组，包括其后方叠页。总览的中心密集分布在选中时服从焦点留白要求；其余组继续保持向外渐疏的椭圆布局。返回时恢复该组原空间位置。
- **组内浏览**：逐张查看组内图片，翻页效果待原型比较；首页封面默认仍为组内第一张。
- **极简首页**：仅在选中画册正上方居中显示半透明文件夹名称，与最上层叠页保持间距。建议使用约 65% 不透明度的浅色文字，不加底板；长名称单行截断，完整名称可按需查看。其余画册不显示文字，默认隐藏品牌标题、完整目录路径、页码、导航、手势说明、常驻状态和摄像头预览。目录选择在首次设置或独立设置层完成；必要的权限与异常提示按需出现。
- **背景材质与光效**：采用偏苹果风格的半透明磨砂玻璃，后方色彩柔和透出；照片和叠页保持清晰、不透明，辅以柔和阴影。背景层不随空间缩放改变模糊尺度；桌面与 Web 的材质呈现边界见产品主文档 6.4。
- **可操作的混沌**：允许少量遮挡、边缘裁切与尺寸差异，但每组封面保留可识别和可选中的区域；布局稳定，不每帧随机或持续漂移。

摄像机保持稳定朝向，不默认自动绕场。空间展示与组内查看分为明确状态：空间支持连续无限缩放和平移，组内支持独立的单图缩放和平移，返回时恢复空间状态。椭圆仅约束默认总览，用户缩放后允许只见局部。选中放大比例是初始参考，不能固定屏幕尺寸抵消空间缩放。照片选择的手势候选为指向后捏合确认，需原型验证，鼠标始终可选图。

## 6. 隐私与权限建议

- 摄像头由用户主动开启，显示当前状态并提供关闭入口。
- 默认目标为本机处理摄像头画面与图片，不上传、不保存摄像头视频。
- 手势模型和其他静态资源的首次获取方式、离线能力在技术方案中明确。
- 权限拒绝、无摄像头或识别失败时，显示可理解的提示并保留常规操作。

## 8. 验收标准草案

- 三个平台按约定的目录访问方式，完成设置目录、自动加载、多图浏览、单图浏览和手势开关流程。
- 目录为空、目录不可用或权限失效时有明确提示；新增或删除图片后，列表按约定刷新机制更新。
- 在约定光照、摄像头、操作距离和测试设备下，切图、翻页和连续缩放可重复完成。
- 单次挥手不连续翻多页，缩放期间不误触切图；离手后视图稳定。
- 空间缩放与单图缩放独立；空间可反复连续缩放和平移，不被自动居中或固定焦点尺寸抵消；任何位置可恢复总览。
- 默认总览保持椭圆疏密分布；选中画册及名称留出安全间距，组内返回后恢复原空间状态。完整验收清单见产品主文档。
- 摄像头权限被拒绝、手部离开画面、模型加载失败时，界面有反馈且可继续常规浏览。
- 暂定体验目标：主要动效接近 60 FPS，手势到视觉反馈延迟争取不高于 150 ms；以原型测量结果校准，尚非性能承诺。
- 识别成功率、误触率、大图和图片数量上限需指定测试样本、测试步骤及目标设备后量化。

## 9. 技术讨论清单

1. 使用场景：个人电脑近距离浏览，还是大屏／展厅远距离展示？
2. 产品形态：macOS、Windows 是否都需要独立安装包？
3. 本机目录：是否递归扫描子目录？首版预计多少张？Web 首版支持哪些浏览器，以及如何处理重新授权与刷新？
4. 分组及空间细节：分组来源、组内排序、照片叠密度、错落程度和选图方式；以视觉与交互原型比较确定。
5. 手势方案：单手与双手的取舍，以及弱光、遮挡、误触与操作疲劳的处理。
6. 平台方案：界面共享方式、桌面容器、摄像头权限和文件访问差异。
7. 渲染方案：图片展示与空间效果的复杂度、性能和内存预算。
8. 是否要求首次启动也完全离线，以及软件签名、安装分发方式。
