# AirGallery · 空间画册产品需求文档

- 版本：v1.2
- 更新日期：2026-11-05
- 状态：需求基线；已进入 v0.1 原型开发，实际完成范围与验证结果见[实现状态](./IMPLEMENTATION_STATUS.md)。本文保留产品目标，不代表全部验收已完成。
- 项目名称：AirGallery（暂定）；当前仓库为 `jetson-photo-wall`，不限定 Jetson 硬件。
- 文档关系：本文作为后续产品需求的主文档；[立项草案](./PROJECT_BRIEF.md)保留项目范围，[技术方案](./TECHNICAL_PROPOSAL.md)记录候选实现。出现产品描述差异时，以本文及用户后续确认为准。

## 1. 产品定位

一个通过摄像头手势操控的本机空间画册。用户设置图片目录后，应用自动加载分组图片，将每组画册以照片叠的形式呈现在可连续缩放的空间中，支持选择画册、组内翻页及单图查看。

体验关键词：空间感、照片叠、椭圆扩散、中心聚焦、连续缩放、半透明磨砂玻璃、克制的界面。

目标平台为 macOS、Windows 和 Web；Web 端读取浏览器所在电脑上的图片目录。

## 2. 已确认需求

| 编号 | 要求 |
| --- | --- |
| C01 | 支持 macOS、Windows、Web |
| C02 | 设置当前电脑的图片目录后自动加载，无需逐张导入 |
| C03 | 图片可能按组组织，每组默认展示第一张 |
| C04 | 每组以多层照片叠放体现多页，而非只显示一张孤立图片 |
| C05 | 首页以图片为主体，不放常驻工具栏、说明或摄像头预览 |
| C06 | 整体具有空间感和混沌感；从中心向外扩散，中心密集、外围宽松，形成椭圆 |
| C07 | 中心选中的画册更大，并与周围画册保持清楚的边距 |
| C08 | 选中画册上方显示半透明文件夹名称 |
| C09 | 摄像头捕捉手势，控制放大、下一张、翻页等操作 |
| C10 | 空间画册支持无限缩放；能力覆盖整个空间，不限于单张图片放大 |
| C11 | 整体背景采用偏苹果风格的半透明玻璃质感，替代原先的不透明近黑背景 |
| C12 | 支持多种可配置、可切换的背景主题；各主题保留半透明玻璃质感 |

以下各节中未包含在此表内的细节属于产品建议；阈值、快捷键、分组规则和性能数值需经讨论或原型校准。

## 3. 产品对象与术语

| 对象 | 定义 |
| --- | --- |
| 图片来源目录 | 用户选择并授权读取的本机根目录 |
| 画册 | 一组有序图片；按子文件夹分组是候选方案，尚未最终确认 |
| 封面 | 组内排序后的第一张图片；“第一张”的排序规则待确认 |
| 照片叠 | 封面加上背后错位的若干照片层，用于表达组内还有图片 |
| 空间视图 | 所有画册所在的可缩放、可平移空间 |
| 选中画册 | 当前焦点画册；更大、留白，顶部显示所属文件夹名称 |
| 组内查看 | 打开选中画册，按顺序查看其中的图片 |
| 单图缩放 | 放大当前图片以查看局部，与空间缩放独立 |

叠页数量只作为多页视觉提示，建议限制可见层数，避免与真实图片数量一一对应。只有一张的画册建议不显示额外叠页。

## 4. 用户流程与界面结构

### 4.1 首次使用

打开应用 → 独立设置层选择本机目录 → 自动扫描并形成画册 → 进入空间首页 → 选择画册 → 打开并浏览组内图片。

手势由用户主动开启；首次可显示短引导，结束后收起。目录授权与摄像头授权分别处理。未开启摄像头时仍可通过鼠标、触控板和键盘浏览。

### 4.2 后续打开

读取目录配置及浏览状态 → 检查目录可用性和权限 → 重新扫描 → 恢复空间位置、缩放及焦点。无法恢复时先显示清楚的恢复入口，再按实际情况回到默认总览。

### 4.3 界面层级

| 界面 | 内容与规则 |
| --- | --- |
| 空间首页 | 照片叠、选中画册的半透明名称；常态不显示其他控件 |
| 组内查看 | 当前图片、组内翻页；必要操作按需出现，避免长期遮挡图片 |
| 设置与引导层 | 图片目录、摄像头开关、手势说明、背景主题、显示偏好、恢复总览 |
| 异常与权限层 | 无目录、权限失效、无图片、摄像头或识别不可用等状态 |

设置入口需可发现，建议首次引导说明如何唤出，并提供边缘悬停入口及快捷键。具体唤出方式待交互原型确定；首页默认不常驻入口图标。

## 5. 目录与画册加载

1. 直接读取原目录图片，原图留在原位置；应用不以复制整库作为浏览前提。
2. 自动扫描图片并按约定规则分组，默认封面为组内第一张。
3. 记住已配置目录；权限或目录失效时允许重新选择。
4. 建议自动发现新增、删除、修改的图片，保留手动刷新；桌面和 Web 的更新时效分别验证，不强行承诺一致。
5. 增量更新尽量保留现有画册位置，避免目录变化导致整片空间重新洗牌。
6. 当前画册被删除时，建议选择附近有效画册；没有可选画册时进入空状态。封面被删除时按稳定排序选择新的首张。
7. 当前图片被删除时切换到组内有效图片；空画册不保留可打开的虚假封面。

首版建议支持 JPEG、PNG、WebP。HEIC、RAW、GIF 动画及其他格式是否纳入需另行确认。

待确定：子文件夹层级、根目录散图如何归组、空目录处理、组内排序、重名画册标识、图片与画册规模。

## 6. 空间布局与视觉规则

### 6.1 默认总览

- 画册从中心向四周扩散，整体外形为横向椭圆。
- 中心附近组间距较小，向外逐渐增大；保留不规则角度、前后深度和适度尺寸差异。
- 椭圆内部有内容，不是空心环；不采用规则网格、整齐同心圈或弧形传送带。
- 允许局部轻微遮挡，但普通画册的封面需保留足够的识别和选择区域。
- 布局应稳定；“混沌”指有层次的错落，不是持续抖动、漂移或每次操作随机重排。
- 采用半透明磨砂玻璃背景，背景色彩柔和透出；照片及细薄叠页边缘清晰，保持视觉主体地位。材质规则见 6.4。

椭圆是默认总览的空间构图。缩放或平移后允许裁切、偏离视口中心；不应为了始终显示完整椭圆而抵消用户缩放。

### 6.2 选中态

- 新选择一个画册时，建议通过短过渡使其成为中心焦点，并放大至明显大于邻近画册。
- 选中画册及其后方叠页的完整边界，与其他画册保留空隙；名称也属于需要避让的区域。
- 周围画册平滑让位；中心密度要求服从选中态的可辨识性和留白。
- 切换选中对象时同步更新名称；不通过闪烁、强光或常驻描边表达选择。
- 自动居中只在用户明确选择或恢复总览时发生，不在用户缩放、平移过程中持续把视图拉回。

### 6.3 文件夹名称

仅选中画册正上方居中显示所属文件夹名称。文字深浅跟随背景主题，保持半透明、无底板，初始视觉参考约 65% 不透明度；按实际背景调整以保证可读性。字号保持可读，不随空间无限缩小或膨胀。

名称与最上层叠页保持间距，不压在图片上。长名称建议单行截断，并可在按需出现的详情中查看完整名称；常态不显示完整磁盘路径。标签随画册离开视口而隐藏，不独立留在屏幕中央。

### 6.4 半透明玻璃背景（新增）

**确认方向**：整体背景具有苹果风格的半透明玻璃质感。参考 [Apple 材质设计](https://developer.apple.com/design/human-interface-guidelines/materials)中的透底、模糊和层次感；不把此参考等同于已实现 Apple 原生 Liquid Glass。

具体视觉与行为建议：

- 背景呈半透明磨砂质感，后方颜色与大轮廓柔和透出；模糊细节，避免干扰照片。
- 使用轻微色调融合、柔和明暗和克制高光表现材质；不固定为纯黑底，也不依赖强烈霓虹或镜面反射。
- 玻璃作用于空间背景层；照片封面及叠页保持清晰、正常不透明，不给每本画册额外套一个玻璃卡片。
- 从后到前的层级为背景内容、磨砂玻璃层、照片空间、名称及按需界面。玻璃模糊不能覆盖照片或名称。
- 缩放和平移只作用于照片空间；玻璃背景保持稳定，不随空间倍率一起放大纹理、改变模糊强度或产生闪烁。
- 在深浅及复杂背景上保持照片辨识度；半透明名称可按背景亮度调整字色、透明度或轻微阴影，但不增加常驻底板。
- 模糊、透明度、色调及高光强度由视觉原型校准，不把单一固定透明度当作跨平台一致性的验收依据。
- 建议支持系统减少透明度或低性能场景的降级，使用有层次的低透明／不透明底色，保证内容和操作可用。

平台体验边界：

| 平台 | 产品目标与验证边界 |
| --- | --- |
| macOS 桌面 | 优先评估系统窗口材质，让窗口后方颜色透过模糊层；需验证窗口、全屏和不同背景下的表现 |
| Windows 桌面 | 评估可用的系统背景材质；目标为相近的玻璃观感，不承诺与 macOS 逐像素相同；版本不支持时提供视觉降级 |
| Web | 用预置主题的页面内背景内容与玻璃层形成同类观感，不承诺网页透出浏览器窗口后方的系统桌面；资源采用本地生成渐变或随应用提供的背景素材 |

桌面材质候选能力依据：[Electron 窗口文档](https://www.electronjs.org/docs/latest/api/base-window)。Web 页面模糊依据：[MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter)。以上为待验证方案，尚未实测。

### 6.5 多背景主题与配置（新增）

**确认要求**：提供多种背景主题供用户配置。首版建议预置以下 6 套主题，具体色值、材质参数和名称对比度以视觉原型校准。

| 主题 | 明暗 | 色彩与材质方向 | 文件夹名称方向 |
| --- | --- | --- | --- |
| 雾紫晨光 | 浅色 | 灰蓝、淡紫与少量柔粉，柔和透光；延续 UI v6，建议作为首次默认主题 | 深石墨色半透明文字 |
| 冰川蓝 | 浅色 | 冰蓝、青灰与银白，冷调清透玻璃 | 深蓝灰半透明文字 |
| 月光银 | 浅色 | 中性银灰与珍珠白，低色偏磨砂玻璃，突出照片原色 | 深灰半透明文字 |
| 玫瑰暮色 | 中间调 | 低饱和玫瑰粉、暖灰与淡杏色，温暖柔光 | 按名称所在背景区域选择深色或浅色文字 |
| 森林薄雾 | 中间调 | 鼠尾草绿、青灰与雾白，克制自然的磨砂层次 | 优先深墨绿；必要时调整浅色文字 |
| 深空石墨 | 深色 | 石墨灰、午夜蓝与微弱紫色透底，低亮度玻璃；保持透底层次，不退回纯黑实底 | 柔白半透明文字 |

主题配置与切换流程建议：

1. 从按需出现的设置层进入“外观 → 背景主题”，首页不增加常驻主题按钮。
2. 每套主题显示名称和小型材质预览；选中后实时预览，清楚标记当前已应用主题和预览主题。
3. “应用”后保存；“取消”、关闭设置层或按返回键撤销未应用预览，恢复进入设置前的已应用主题。
4. 首次使用默认“雾紫晨光”。额外提供“跟随系统”模式：建议系统浅色映射“雾紫晨光”、深色映射“深空石墨”；选择固定主题后停止跟随，直到用户重新启用。
5. 已应用的主题或跟随模式保存在当前设备／浏览器的应用偏好中，下次打开恢复。主题按应用全局生效，不因切换图片目录而改变；不引入账户和跨设备同步。
6. 固定主题切换、系统模式变化时采用短暂平滑过渡；不自动轮播背景，不在用户浏览时自行更换配色。

主题作用范围与不变量：

- 主题控制背景色调、透底综合色、模糊与透明度参考、高光，以及名称和按需界面的文字／控件配色。界面文字与控件需同步切换，避免浅色主题出现看不清的白字。
- 主题不改变照片色彩或透明度、分组排序、椭圆布局、选中对象、缩放、平移、组内当前页及摄像头状态；切换后不重新扫描目录或重新生成照片布局。
- 各主题都保持苹果风格的玻璃质感、选中留白与照片清晰度。全局减少透明度／性能降级策略优先于主题材质参数；即使降级也保留该主题的色彩方向。
- 桌面端将主题色调与可用的系统材质结合，Web 使用对应的页面内主题背景；追求同一主题可辨认，不要求底图或透底颜色逐像素相同。
- 预置背景及主题配置随应用提供，不需要额外下载远程壁纸；这不改变手势模型等资源的离线要求仍待确认的状态。
- 已保存主题失效或预览资源不可用时，回退默认主题并在设置层按需说明，核心图片浏览不受影响。

首版配置以预置主题选择及跟随系统为主。自定义壁纸、用户配色编辑、主题导入导出与自动轮播暂不纳入；透明度和模糊是否开放为用户滑杆，留待原型评估，尚未作为确认需求。

## 7. 空间无限缩放（核心新增）

### 7.1 产品含义

用户可反复、连续放大和缩小整个画册空间，从远处总览靠近局部，再缩回总览；不采用有限的“远／中／近”三挡切换，也不把体验限定为固定几档倍率。

“无限缩放”在本文中指用户可以持续进行缩放操作的空间体验。图片内容和数量仍来自实际目录，不生成重复画册或递归内容；单张原图的细节受原始分辨率限制。极端尺度的可用性、数值稳定及设备承受范围须通过原型验证；若实现需要可感知的硬边界，应明确列为待决取舍，不静默改为固定倍率封顶。

### 7.2 缩放行为

| 项目 | 产品要求／建议 |
| --- | --- |
| 作用对象 | 空间模式缩放所有画册及其相对间距；不会自动打开画册或翻动组内图片 |
| 连续性 | 可持续、多次缩放；手势重新捏合后从当前尺度接续，不跳回初始倍率 |
| 锚点 | 建议鼠标以指针位置、双手以两手中点为锚点，快捷键以视口中心为锚点 |
| 平移配合 | 允许空间平移，以浏览放大后处于视口外的画册 |
| 选中关系 | 缩放不改变当前选中画册，不因照片变大而自动进入组内查看 |
| 选中突出 | 保留选中组相对普通组的突出关系；不把其屏幕宽度永久锁死为视口 1/4 |
| 选中留白 | 在可见范围内让其他组避开选中组及名称；不可用缩小焦点或反向缩放抵消用户操作 |
| 深度放大 | 允许选中组大于视口，用户可继续平移；超出视口的照片不必强行挤回屏幕 |
| 深度缩小 | 允许画册缩至难以辨认；建议按比例降低叠页与细节，但不随机删除实际数据 |
| 无内容区域 | 允许暂时进入空白位置；必须有可靠的恢复总览操作 |
| 返回与重置 | 恢复总览将所有有效画册按默认构图适配视口，选中有效时保留；恢复动作独立于缩放输入 |
| 状态保持 | 打开再关闭画册，恢复进入前的空间缩放、平移与焦点 |

### 7.3 与单图缩放的边界

空间模式中，缩放改变整个空间；打开画册后，缩放只改变当前图片。两者保存独立状态，不互相继承倍率。

建议切换到组内下一张时恢复新图片的适配窗口比例；退出组内查看后恢复原空间状态。是否保留每张图片的个人缩放记录为后续扩展。

### 7.4 动效与清晰度

操作期间连续反馈，不等待动画完成再响应下一次缩放。停止后不意外惯性漂移；追踪丢失时保持最后有效状态。

远处优先展示封面与简化叠页，靠近后平滑补充清晰图片。画质切换不能引起位置跳动或封面内容改变。缩放时不重新随机布局，不穿模、不闪白、不突然镜像翻转。

## 8. 操作与手势建议

动作映射为候选，需验证成功率、误触和使用疲劳。必须先区分所处模式，再解释同一手势。

| 意图 | 空间模式 | 组内查看模式 |
| --- | --- | --- |
| 双手捏合后改变距离 | 连续缩放整个空间 | 缩放当前图片 |
| 单手捏合拖动 | 拖动画册空间 | 平移已放大的当前图片 |
| 指向后捏合确认 | 选择画册；打开操作需与选择明确区分 | 不隐式切图 |
| 单手比 V 保持约 0.6 秒 | 打开中心选中画册，显示短暂进度提示 | 不触发操作 |
| 单手握拳保持约 0.6 秒 | 不触发操作 | 退出画册并恢复原空间状态 |
| 单手持续向镜头比 👍 | 持续出现随机夸奖弹幕，自上向下 | 同左；保留当前照片与页码，不误识别为握拳关闭 |
| 双掌先分开再快速拍手合拢 | 不触发操作 | 在当前照片上播放约 7 秒大型多层烟花与音效，不修改原图；约 2.2 秒冷却，可静音，F 键或按钮也可预览 |
| 左右挥手 | 候选为切换焦点画册，待与空间拖动比较 | 上一张／下一张，每次最多一张 |
| 返回 | 通过按需控件或快捷键返回总览 | 退出画册并恢复原空间状态 |
| 暂停手势 | 设置层中明确开关 | 同左 |

点赞夸奖雨：只要持续识别到单手 👍，就不断随机生成彩色夸奖文字，从屏幕上方分列错落下落，无需保持计时或重新放下再举起。松手、关闭摄像头或识别超时即停止新增，已有文字自然落完退出。文字数量必须有上限，不能随持续时间累积，不挡鼠标和触控操作。翻页、返回时可继续下雨；打开设置或切到后台立即清理。减少动态效果时定时刷新静态夸奖卡片。P 键可手动进行有限时长预览，无需摄像头。

烟花视觉采用日漫花火大会氛围：大花冠、多层花芯、密集发光拖尾、金色垂柳，错落连发后以多束齐放收尾。原照片始终保留，动画不能阻塞翻页或返回；尊重减少动态效果偏好。

普通输入应覆盖核心操作：指针选择、双击或确认键打开、滚轮／捏合缩放、拖动平移、方向键组内翻页，以及返回、恢复总览、设置和暂停手势的可发现入口。具体鼠标键位、快捷键与触控板映射待原型统一。

冲突优先级建议：双手缩放期间锁定缩放，禁止同时翻页；拖动期间禁止把同一轨迹识别为挥手。动作结束或丢手后释放锁定；重新识别需建立新起点，避免跳变。摄像头镜像显示与挥手方向映射必须统一测试。

## 9. 状态与异常

| 状态 | 期望行为 |
| --- | --- |
| 首次未配置目录 | 独立设置层选择目录，不长期占据已配置首页 |
| 扫描中 | 显示真实加载状态，已加载画册可逐步出现；允许取消或重选 |
| 目录为空／没有支持图片 | 说明原因，提供更换目录或刷新入口 |
| 目录权限失效／路径不可用 | 请求重新选择或授权；保留可恢复配置，不呈现为正常空库 |
| 个别图片损坏 | 跳过或显示按需错误反馈，其余画册仍可浏览 |
| 摄像头被拒绝／不存在／识别失败 | 保留常规输入，允许重试，不阻塞图片浏览 |
| 手部离开画面 | 保持当前画面，不继续缩放、不连续切图 |
| 缩放和平移后迷失 | 可通过明确入口恢复总览 |
| 运行负载较高 | 优先降低装饰和远景细节，保留输入响应和当前图片清晰度 |

## 10. 平台、隐私与质量目标

- 三个平台共享上述产品规则；最低系统与浏览器版本另行确认。
- Web 必须在用户授权后访问本机目录；目录恢复与刷新策略按浏览器能力验证。
- 图片和摄像头画面默认在本机处理；不上传原图，不保存摄像头录像。
- 摄像头由用户主动开启，可在设置中明确关闭；首页不常驻预览不代表摄像头自动启动。
- “首次启动完全离线”是否为首版要求待确认，模型与资源的获取方案在选型后明确。
- 体验目标建议沿用主要动效接近 60 FPS、手势到反馈争取不高于 150 ms；需要指定硬件、光照、距离、目录规模和测量方法后校准，当前不是已验证承诺。
- 内存与图片数量存在实际预算；空间缩放不能要求一次加载全部原图。具体支持规模与压力测试样本待确定。

## 13. 待决问题

1. **分组规则**：是否一个子文件夹对应一本画册？是否递归？根目录散图如何处理？
2. **第一张排序**：文件名自然排序、拍摄时间或自定义顺序？
3. **主要场景与规模**：近距离电脑浏览还是大屏隔空操作？预期多少画册、每册多少张、单图大小？
4. **无限缩放细节**：本文按整个空间可持续缩放理解；极远／极近的呈现策略与可感知边界须原型验证后确认。
5. **手势映射**：选择与打开如何区分，组间切换、组内翻页、空间平移及返回采用哪些动作？
6. **翻页效果**：组内使用纸页翻动、抽取照片还是平滑切换？
7. **运行环境**：最低系统、浏览器、离线要求、图片格式，以及安装包分发要求。
8. **玻璃与主题细节**：建议 6 套主题的最终色彩、材质参数和深浅文字策略；桌面不支持原生材质时的降级效果，以及是否开放模糊／透明度滑杆。默认主题和系统映射按 6.5 的建议进入原型验证。

## 14. 视觉基线与变更

最新静态视觉参考：[UI v6](./design/airgallery-spatial-ui-v6.png)，[设计说明](./design/airgallery-spatial-ui-v6.md)。它展示“雾紫晨光”的色彩方向、椭圆分布、中心选中、叠页与半透明名称；浅色主题实际名称应按可读性改为深色半透明文字，图中白字不作为固定要求。其他主题尚未分别出图，v5 保留为历史布局参考。背景为静态合成示意，实际照片不做插画化处理。空间无限缩放、平移、组内翻页、主题切换及动态玻璃效果需交互原型验证，静态图不能作为这些能力已实现的证据。
